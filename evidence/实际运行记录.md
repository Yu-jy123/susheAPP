# 模拟器实际运行记录

日期：2026 年 11 月 14 日。开发环境：DevEco Studio 6.1.1；模拟器：HarmonyOS 6.1.0（API 23）TripleFold。包名：`com.yujy.dormautomationlab`。

## 构建和测试

执行 `assembleHap --mode module -p product=default -p module=entry -p buildMode=debug --no-daemon` 成功，详见 [build-log.txt](build-log.txt)。执行 `test -p module=entry -p coverage=false --no-daemon`，实际结果为 9 项通过、0 项失败、0 项错误，详见 [test-result.txt](test-result.txt)。

## 实际操作

1. 将构建的 HAP 安装到模拟器，用 `aa start -a EntryAbility -b com.yujy.dormautomationlab` 启动。总览页显示照明、空调、窗帘、加湿器四类设备，见 [overview.jpeg](overview.jpeg)。
2. 在“环境”页加载“炎热干燥的白天”（31°C、30%、850 lx）。总览页观察到空调、加湿器运行；环境与设备的实际截图见 [scenario-day-environment.jpeg](scenario-day-environment.jpeg)、[recovery-before.jpeg](recovery-before.jpeg)。
3. 白天场景下结束应用进程并重新启动。重启前后总览均显示照明、空调、加湿器运行，窗帘关闭；最近执行仍为“照明开启”。环境仍显示 31°C、30%、850 lx，见 [recovery-before.jpeg](recovery-before.jpeg)、[recovery-after.jpeg](recovery-after.jpeg)、[recovery-environment.jpeg](recovery-environment.jpeg)。这里验证的是实际模拟器进程重启后的本地存档恢复。
4. 将温度从 32°C 调到 33°C，同一页面立即显示 33°C，见 [environment-verified.jpeg](environment-verified.jpeg)。开发中曾发现环境值在当前页刷新滞后，修正状态读取方式并重新编译安装后复测通过。
5. 打开“规则”页，看到五条默认规则及“昏暗且湿度未超限时开灯”的双条件规则，见 [rules.jpeg](rules.jpeg)。打开“日志”页，看到条件命中、设备动作及“状态未变化”的记录，见 [logs.jpeg](logs.jpeg)。
6. 在规则编辑器新增 `Night off`：`light < 200`、照明关闭、优先级 10。加载“凉爽昏暗的夜晚”（20°C、65%、80 lx）后，执行日志首先记录新规则关闭照明，随后记录默认双条件开灯规则 R3 命中但动作冲突被跳过。实测截图见 [scenario-night.jpeg](scenario-night.jpeg)、[conflict-log.jpeg](conflict-log.jpeg)。随后在规则页将 `Night off` 停用，页面反馈“Night off已停用”。

Windows Game Bar 对模拟器窗口的实际录制文件为 `运行录屏.mp4`。该文件保存在本地交付目录，作为独立附件提供，不上传 GitHub。录制过程中弹出模拟器输入法首次使用同意提示，因此此段录屏中的规则新建尚未完成；后续实际新建与冲突处理另以界面截图和日志记录提供证据。
